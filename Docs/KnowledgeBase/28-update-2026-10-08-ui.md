# 2026-10-08 UI 基础闭环

本轮以现有 CommonUI／CommonInput／UMG／Slate 实现自有框架，未引入 CommonGame、CommonUser、ModularGameplayActors，未改变 GameInstance／LocalPlayer／Controller 父类。

## 运行链

GameInstance 玩家加入／移除 → HodgeUIManagerSubsystem → 当前 Controller 的 HodgePrimaryGameLayout／共享数据源 → Experience AddWidgets → Game 层 HUD 与 LocalPlayer Context 插槽 → HealthComponent／ASC 数据。

根布局有 Game／GameMenu／Menu／Modal 四层。每个 LocalPlayer 独立持有根布局；Controller 更换时销毁旧布局，Pawn 更换只重绑数据。InputData 放在 DefaultGame.ini；Escape Action 放在 DefaultInput.ini；HodgeGameViewportClient 配置放在 DefaultEngine.ini。

HodgeExperienceActionSet 是原生 DataAsset，AssetManager 的该类型扫描 bHasBlueprintClasses=false，并加入 /Game/Main/UI，否则冷启动 Client Bundle 会遗漏正式 HUD。

## 正式入口

`/Game/Main/UI/EAS_HodgeGameplayUI` 已加入默认 Experience。Root／HUD／血条／基础技能栏／菜单／确认框、按钮与技能项模板及输入数据共 11 个正式资产在 Main/UI。菜单的 ConfirmationClass 指向正式确认 WBP。正式 WBP 已有 Designer 控件树和 Graph，运行时不再生成整张页面布局。六个业务原生控件类已归档；一个 HodgeGameplayUIDataSource 按 LocalPlayer 共享并负责玩法读取。根布局通过四个 BindWidget 容器注册层。

菜单只阻止自己的玩法输入，打开时释放按住的能力、清空连段缓存及移动意图；退出不重放菜单期间的输入。血条订阅当前 Pawn 的真实生命属性，技能栏按实际输入 Tag 查询能力／冷却，不驱动服务器属性。
