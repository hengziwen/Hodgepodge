## 新增实现

`UHodgeAbilityTimeline`（数据资产）与 `UHodgeAbilityTask_PlayTimeline`（唯一消费者）。几点与旧版的关键差异：

- **单一 `Events[]` + `Kind`**；字段**按 Kind 拆开**：`WindowTag` / `PointEventTag`、`WindowEffectClass` / `PointEffectClass`，无关字段用 `EditConditionHides` 互相隐藏；删除 `DisplayName`，列表用 `TitleProperty=EventID`。
- **统一 Scheduler**：`CollectNodes`（把 Window 展开成 `WindowBegin` / `WindowEnd`，Point 展开成 `PointFire`）+ `SortNodes`（`Time → NodeKind → Priority → EventIndex`），**`InitializeTimeline` 与 `TickTask` 共用同一套**，所以"从起点接续"与"正常推进"的调度顺序一致。
- **两个账本**：`ActiveWindowIndices`（tag，按下标）与 `WindowEffectHandles`（GE，按句柄）；清理幂等且对"改 ASC 引发的重入"安全。
- **两道防线**（`EnterWindow`）：写完 tag 后先查 `bStopped || bCleanedUp` 再施加 GE；施加后若发现已清理则立刻补偿移除、施加失败不入账。`ExitWindow` 则是**相反**约束：它已先摘掉账本条目，**不能**提前返回。
- **`TickTask` 的时钟倒退守卫**放在累加之前（`WorldDelta <= 0` 直接 return，且先更新采样点）。
- **`InitializeTimeline` 的语义边界**：`StartOffset` 是"状态恢复 / 接续"，**不是历史重放** —— 历史 Point 不补发、已结束窗口不重放，窗口 GE 的 `OnActive` / Cue / Period 以 `StartOffset` 为实际发生时刻。
- **数据校验**按 `Kind` 分流重写（`EventID` 唯一性、合法时间范围、同 `WindowTag` 重叠、Window GE 必须 Infinite、Point GE 禁 Infinite、`LocallyControlledOnly + PointEffectClass` 为 Error 等）；`PostEditChangeProperty` 用 **`StableSort`**。

### 取消路径证据（在窗口中间调用 `clear_ability(handle)`）

`Active` 窗口生效中（`Active=1`、`GE_COUNT=1`）时调用 `asc.clear_ability(handle)`：

| 时刻 | Windup | Active | Recovery | Point 标签 | Interrupted | GE 实例 |
|---|---|---|---|---|---|---|
| 取消前 | 0 | **1** | 0 | 0 | 0 | **1** |
| 取消后立刻 | 0 | **0** | 0 | 0 | 0 | **0** |
| +12s（已越过 0.5 与 0.9） | 0 | 0 | **0** | **0** | 0 | 0 |

三条结论：

1. **取消路径的清理正确**：`OnDestroy` → `ClearAllWindowState` 把 tag 账本与 GE 账本**都**清干净了（GE 未泄漏）。这正是设计里那条"无条件兜底"路径，此前只在**自然结束**上间接验证过。
2. **时间轴真的停了**：取消之后再没出现 `Recovery`、Point 也没派发 —— 不存在"停不下来还在 tick 的幽灵时间轴"。
3. **`Interrupted` 不派发是符合设计的**：`ClearAbility` 走的是 `AbilityCancelled`（头文件写明"不广播任何事件"），而 `Interrupted` 的语义是"被外力真正抢占"。设计 §8 早已列出"`Interrupted` 目前没有触发者；Ability 被取消走 `OnDestroy`，不经过 `StopTimeline`"。因此该分支**仍未被执行**（见下"未验证"第 1 项）。

> **顺带发现（`Interrupted` 是死分支）**：全项目搜索确认 **没有任何调用点**会传 `StopTimeline(EHodgeTimelineStopReason::Interrupted)` —— 枚举值、`FireSystemEvent`、校验用的标签都存在，但当前无人触发。这不是缺实现，而是"等第二阶段接入被抢占语义"的预留通道（设计 §7.2 / §8 已声明）。
