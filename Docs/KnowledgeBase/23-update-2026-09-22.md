## 新增实现

### 1. 取消窗口标签（`HodgeGameplayTags.h/.cpp`）

`Status.Attack.*` 下新增两个 **loose tag**，由 `UHodgeAbilityTask_PlayTimeline` 按 Window 区间自动加减（本轮唯一的新标签）：

```text
Status.Attack.Cancel         // 当前允许"因某种意图而结束这次攻击"（授权）
Status.Attack.Cancel.Move    // 其中一种意图：移动
```

它与既有阶段标签是**两件事**，两者会分叉，所以必须各自配 Window：

| 标签 | 语义 | 举例 |
|---|---|---|
| `Status.Attack.Recovery` | 状态描述：此刻处于后摇 | 后摇 `[0.45, 0.90)` |
| `Status.Attack.Cancel.Move` | 授权：此刻允许被移动取消 | 移动取消只开 `[0.60, 0.90)` |

具体意图由子标签表达，便于以后并列扩展 `Dodge` / `Jump` / `NextAttack`。**标签存在本身不代表消费方已接线**。

### 2. `UHodgeAbilityTask_WaitMoveCancel`（新 AbilityTask）

落位 `Public|Private/AbilitySystem/Abilities/HodgeAbilityTask_WaitMoveCancel.*`。它把"移动取消后摇"里**条件判定 + 信号广播**这一环单独拆出来，三层职责分工是它存在的理由：

```text
Timeline       → 允许不允许移动取消（授权，由资产里的 Window 区间决定）
Input / Hero   → 玩家到底有没有想移动（意图）
Attack Ability → 满足两个条件后这次攻击应该怎么结束（策略，第一版是 EndAbility）
```

- 工厂：`WaitMoveCancel(OwningAbility, CancelWindowTag, MoveIntentThreshold = 0.1f)`，条件成立时广播 `OnMoveCancel`（**只广播一次**），随后自结束。
- 两个信号都**变化驱动**，不做每帧轮询：窗口标签走 `ASC->RegisterGameplayTagEvent`，移动意图走 `UHodgeHeroComponent::OnMoveIntentChanged`。
- 订阅用弱引用并在 `OnDestroy` 解绑（任务比 ASC / HeroComponent 短命）；广播前先立 `bSucceeded`，因为监听者常会在回调里**同步** `EndAbility`，本任务会在广播途中被销毁。
- **本地控制端语义**：移动意图只存在本地控制的玩家身上，服务器对远端玩家的 Pawn 永远看不到它——这不是缺陷（取消由 Ability 的 `EndAbility` 经 GAS 预测复制收敛到服务器）。**不要为了"两端一致"把移动意图复制上去**，那会造出两个决策源。推论：AI / 模拟代理找不到 HeroComponent 时只订阅标签，条件**永不成立**。
- 与 [`UHodgeAbilityTask_PlayTimeline`](07-gas.md) 一样，**C++ 调用方必须自己调 `ReadyForActivation()`**，漏掉时静默不跑；蓝图 latent 节点会自动补。

### 3. `UHodgeHeroComponent` 的"移动意图"信号（输入层）

移动意图是"用移动取消后摇"唯一的输入信号，属于输入层、不属于 Timeline：

- `HasMoveIntent(float Threshold = 0.1f)` / `GetMoveIntent()` / `OnMoveIntentChanged(bool)`（BlueprintPure / BlueprintAssignable）。
- **读的是原始输入量**（`Input_Move` 的二维值），不是角色位移：攻击期间角色被蒙太奇钉住也不影响判定。
- `Input_Move`（Triggered）在**最前面**记录意图，位于任何提前 return 之前；新增 `Input_MoveStopped` 绑到 `ETriggerEvent::Completed` 与 `Canceled` 以清零。只接 `Triggered` 会让意图"粘住"（松手、切换 InputContext、失焦都不回 0），依赖它的取消逻辑会持续**假阳性**。
- `OnMoveIntentChanged` **只在布尔结果翻转时广播**：推杆过程中 `Input_Move` 每帧触发，不能每帧广播。
- ⚠️ **设计约束（已写进头文件注释）**：采集点在 `Input_Move` 里，位于任何"屏蔽移动输入"之前。若以后用 `SetIgnoreMoveInput` / `DisableMovement` 让攻击期间不能移动，`Input_Move` 将不再回调，移动意图恒为 `false`，依赖它的取消逻辑会**静默失效**。**禁止移动不要用屏蔽输入来实现。**

### 4. CodexText 实验区精修 + Build.cs 编辑器依赖

- `CodexText` 动画实验继续扩展：`UHodgeGroundedLocomotion` 增加上半身 Overlay、左手握持（`SetLeftHandGrip`）、步幅 / 地形 IK 相关字段；`UHodgeGroundedAuthoring` 增加 `RefineGroundedTransitions` / `AddStrideLayer` / `AddTerrainLayer` / `AddCombatLayer` 四个编辑器辅助函数；`NativePostEvaluateAnimation` 换成 `NativeUninitializeAnimation`。
- `Hodgepodge.Build.cs` 的编辑器专用块（`Target.bBuildEditor`）新增 **`AnimationWarpingRuntime`、`AnimationWarpingEditor`**（供 CodexText 用 UE 5.5 的 Stride Warping / Foot Placement）。**这是 Editor-only 依赖，不进 Runtime 构建**；Runtime 模块仍未依赖 ALS。
- 这些属于**独立实验**，不走主 Hero 的 GAS / Experience 链，主体系没有 C++ 引用。详细资产、验证结果与限制见 [CodexText 地面运动实验说明](../../Tools/LocomotionLab/README.md)。
