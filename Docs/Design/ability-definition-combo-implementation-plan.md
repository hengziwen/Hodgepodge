# 单段技能与连招系统：第一版执行计划

> 依据：[设计文档](ability-definition-combo-graph.md)，尤其是第 13 节用户决策。
> 状态：待执行。本次只拆分步骤，没有开始修改运行时代码或资产。
> 范围：第一版运行时、五段普攻配置及验证。组合触发 B、网络时间容差 B、Section 跳转、循环和图形技能编辑器不在本轮实现范围。

## 执行原则与阶段依赖

按以下顺序推进，每步达到验收条件再进入依赖它的下一步：

`1 技术契约 → 2 数据结构 → 3 授予与初始化 → 4 Montage 播放 → 5 Timeline 时钟 → 6 单段 GA → 7 连招与输入 → 8 网络 A → 9 五段配置 → 10 默认配置迁移与回归`

执行身份、标签账本和网络消息边界从第 1 步设计，第 3～7 步按该契约实现；第 8 步完成权威核验和联机收敛，不是在单机完成后才临时补网络架构。

新系统先用专用测试配置验证，第 10 步才替换默认 PawnData 的实际使用链路。旧普通攻击和旧 Timeline 独立时钟路径保留作为迁移基线，不在功能接通前删除。

每个步骤可以作为独立工作单元交付，不要求自动创建任务、分支或提交。实现时遵循项目 AGENTS.md 和 AI_DEVELOPMENT.md；保留工作区已有改动。

## 1. 固定技术契约与迁移基线

**工作内容**

- 重新核对 PawnData → AbilitySet → PlayerState ASC → PawnExtension / HeroComponent 的实际调用链及现有资产引用。
- 明确 Definition 与原装备来源如何同时进入授予上下文，不直接覆盖 SourceObject 的已有业务语义。
- 明确当前连招会话、AbilitySpec、GA 执行和 Montage / Timeline 实例之间的身份关系，区分本地对象身份与可在网络中关联的执行序号。
- 明确协调器挂接和解绑方案。按设计文档保留 PlayerState / ASC 所有者侧建议，不将其误记为用户已经明确选择的位置。
- 定义授予/撤销、窗口变化、执行结束、输入意图、跳转请求及确认/拒绝的接口职责。
- 记录现有默认授予、输入映射和旧回归结果，列出后续确实需要修改或备份的资产。

**交付物**：设计文档中的技术契约补充、实际文件/资产影响清单。

**验收条件**：所有运行时状态都有拥有者和清理入口；网络身份不依赖跨端裸 UObject 指针；不改变用户已确认的玩法规则。剩余常规技术选择依据代码落实并记录，只有影响已确认行为的冲突才重新讨论。

## 2. 定义数据资产、表格结构与校验

**工作内容**

- 引入 AbilityDefinition、ExecutionConfig、开始混合、自然结束 BlendOut、主动停止 BlendOut 和 TimelineTaskConfig。
- 引入 ComboDefinition、ComboRow、ComboTransition。正式类型名沿用 Hodge 前缀和 Public / Private 对应目录。
- 实现 RowName / ComboTag 一致性、目标节点存在、AbilityTag 可解析、触发字段互斥及参数合法性校验。
- 固定状态条件 All / Any、身份精确匹配、优先级及同优先级的稳定选择规则。
- 数据层提供第一版范围约束：不开放 Section 起播、任意起点、主动跳转、循环和回退。
- 配置输入缓存默认 0.3 秒、容量 1、新输入替换旧输入；标明组合触发未来扩展位置，不制作已经可用的假字段。

**主要落点**：`Public/Data`、`Private/Data`，以及必要的 GameplayTag 声明。

**交付物**：可在编辑器创建的数据类型与可复用校验逻辑。

**验收条件**：Editor / Game 构建通过；有效最小配置可加载；缺失目标、双触发、空触发、非法时间等错误能定位到具体资产、行和边。还不替换默认授予。

## 3. 接通 Definition 授予与 PawnData 初始化

**工作内容**

- 扩展 AbilitySet 配置 Definition，由服务器授予对应 AbilityClass，并向 GA 提供 Definition 与原授予来源。
- 建立当前授予上下文内 AbilityTag → Definition / SpecHandle 映射，检测同一上下文中的歧义。
- PawnData 增加 ComboDefinition 配置入口，与 AbilitySet 的技能授予职责分离。
- 处理定义资源加载、GC 持有、客户端获取配置及授予撤销；不能假定服务器内存对象会自动复制到客户端。
- 接入 ASC / Pawn 初始化与解绑，确保重复初始化不重复授予，更换 Pawn 不保留旧会话和输入。
- 兼容仍使用旧 AbilitySet 条目的非连招能力，不批量迁移无关技能。

**主要落点**：HodgeAbilitySet、HodgePawnData、PlayerState / PawnExtension 的必要接入点及授予上下文。

**交付物**：使用专用测试 PawnData 授予一个 Definition 的完整链路。

**验收条件**：服务器授予一次，拥有端可读取正确 Definition；同类不同来源可明确区分；移除与重新绑定不残留 Spec 映射。执行双人授予和配置可用性检查，不能只看 C++ 编译。

## 4. 扩展 GAS Montage 播放与混合设置

**工作内容**

- 在项目 ASC / 播放 Task 中支持 ExecutionConfig 的播放倍率、BlendIn、NaturalBlendOut 和 StopBlendOut。
- 保留 GAS 动画能力归属、预测及 Montage 复制链路，不绕过 ASC 直接播放来代替集成。
- 为每次播放提供可靠的实例身份和位置读取入口，区分自然结束、取消、外部打断和主动接段。
- 第一版采用 Standard 默认方式，曲线独立配置；不修改共享 Montage 资产属性实现运行时覆盖。
- 所有停止请求核验动画归属，旧任务不能停止后来启动的新 Montage。

**交付物**：可独立验证的 GAS Montage 执行接口/Task。

**验收条件**：开始、自然结束、主动停止三类混合配置分别生效；倍率正确；停止旧播放不影响新播放；双人环境中拥有端、服务器和观察者的播放与停止可核对。完整连招预测留到第 8 步。

## 5. 扩展 Timeline 动画时钟与实例窗口查询

**工作内容**

- 保留 Independent 时钟，新增绑定当前 Montage 执行实例的时钟来源。
- 从动画播放范围派生有效 Duration，不再手工匹配长度，不在运行时写回共享 Timeline。
- 使用动画源时间调度窗口和 Point，正确处理播放倍率，避免重复缩放。
- 提供当前执行实例的窗口视图和窗口变化通知；ASC 聚合标签仍可查询，但不充当连招窗口归属证据。
- 保留事件排序、窗口/GE 账本和幂等清理；中断时释放本次执行资源。
- 处理位置校正不重复派发已消费副作用；显式拒绝第一版不支持的主动跳转/循环配置。

**主要落点**：HodgeAbilityTimeline、HodgeAbilityTask_PlayTimeline，及第 4 步的播放上下文。

**交付物**：动画关联 Timeline 模式与带执行身份的窗口查询接口。

**验收条件**：1 倍和非 1 倍播放下窗口对应动画源时间；暂停不继续推进；提前停止正确清理；同名并行窗口不会相互授权；旧 Independent 模式的回归仍通过。

## 6. 完成单段 Definition 驱动 GA

**工作内容**

- 建立共用的单段执行基类，从授予上下文读取 Definition。
- 完成校验、Commit、Montage / Timeline 启动、自然完成、取消和外部打断流程。
- GA 不持有五段数组，不决定下一段，不独占跨段输入缓存。
- 为协调器提供带执行身份与结束原因的通知，避免旧 GA 回调影响新节点。
- 创建一个测试 GA 和一个 Definition，验证实际 Blueprint Defaults、引用和保存结果。

**交付物**：一个可通过 GAS 激活的单段技能闭环。

**验收条件**：一次激活只播放配置的一段；无效定义和 Commit 失败安全结束；所有结束路径清理任务、窗口及委托；蓝图编译、重载持久化及单人 PIE 均通过。

## 7. 实现连招协调器、输入缓存和切换流程

**工作内容**

- 维护 Entry、当前节点、执行序号、当前 Spec、节点 GrantedTags 账本与单槽输入缓存。
- 将连招输入转为 InputIntent；保留非连招能力原输入路径。五个单段 GA 不同时绑定同一近战输入直接激活。
- 实现输入边/事件边筛选、窗口变化重评估、Required / Blocked 条件及稳定优先级。
- 实现默认 0.3 秒缓存过期、新输入覆盖、成功消费及失败后的清理规则。
- 先完成 Entry → 第一段 → 第二段，再处理自然结束、移动取消、外部打断和撤销。
- 有效接段优先于移动取消；输入已过期或接段条件不满足时不能阻止合法移动取消。
- 实现防重入切换：预检查失败且旧 GA 未结束时继续当前段；进入实际切换后失败则回 Entry，清理标签和输入。
- 分别维护节点 GrantedTags 与执行窗口，过滤旧执行的 GameplayEvent / AbilityEnded。

**主要落点**：连招协调组件、Hero/ASC 输入路由、单段 GA 通知接口。

**交付物**：两段连招最小运行闭环及调试状态输出。

**验收条件**：一次点击不串跳两段；过期、替换、空输入、标签阻塞、同优先级、事件边、窗口归属、接段/移动竞争和切换失败均有覆盖。更换 Pawn、移除技能和重复初始化无状态残留。

## 8. 完成网络方案 A 的权威判定与预测收敛

**工作内容**

- 接通带输入序号、会话/执行身份的跳转请求与确认/拒绝，服务器独立核验源节点、窗口、状态及目标能力。
- 服务器按请求收到并处理时的当前权威窗口判断，不回溯客户端输入时间，不把本地 0.3 秒缓存当作网络宽限。
- 拒绝过期执行、重复消费、错误来源或窗口关闭的请求，不把它们延后套用到新执行。
- 完成预测节点、动画、标签与输入状态的确认和拒绝收敛；避免预测标签与复制标签重复计数。
- 检查模拟代理 Montage 的播放和停止，以及技能撤销、Pawn 变化时的网络清理。

**交付物**：第一版网络协议及双人测试记录。

**验收条件**：Listen Server 主机、拥有客户端和观察者正常；模拟延迟/丢包下可接受合法请求、拒绝迟到/重复请求并最终收敛。迟到导致漏接属于 A 的已知体验限制，状态残留或重复执行不属于可接受限制。

**阶段边界**：本步不实现网络 B 的历史核验或时间容差，不以 A 的通过结果代表 B 已验证。

## 9. 配置五段普攻资产并完成专用场景验证

**工作内容**

- 创建 `GA_Attack_1`～`GA_Attack_5`，共享单段执行基类。
- 创建五份 AbilityDefinition，分别关联用户指定的 `AM_Attack01_Montage`～`AM_Attack05_Montage` 和对应 Timeline。
- 创建 Combo DataTable：Entry、Light.01～Light.05；配置轻攻击跳转与后半段窗口条件。
- 创建 ComboDefinition，使用已确认的默认缓存和结束规则；自然结束与主动停止混合分别配置。
- 使用专用 PawnData / AbilitySet 测试配置接入五段，不提前覆盖用户默认配置。
- 经 MCP 检查蓝图编译、配置引用、保存以及重新打开后的持久化；修改已有资产前检查并备份。

**交付物**：可运行的五段资产集合、输入操作说明和逐段配置说明。

**验收条件**：五段按表跳转，单击只打一段；在窗口前 0.3 秒以内和以外分别验证接段/过期；移动取消与接段优先规则符合设计；单人及双人均验证。不得仅沿用旧测试中“很早点击也能接段”的预期。

## 10. 迁移默认配置、完整回归与交付

**工作内容**

- 备份并检查 `/Game/Main/Data/DA_Dafult_PawnData` 及实际关联的 AbilitySet，切换到新 ComboDefinition / Definition 授予链。
- 移除默认链路上会竞争同一输入的旧普攻授予，但不顺手删除旧 GA、第三方资产或用户未提交内容。
- 在默认 `ThirdPersonMap` 验证真实生成玩家的授予、输入、五段跳转与取消，不以临时 GiveAbility 代替验收。
- 回归非连招技能输入、旧 Timeline 独立模式、重复初始化、能力撤销和 Pawn 更换。
- 记录实际构建命令、蓝图编译/保存、PIE、联机、延迟测试结果；恢复临时 PIE 设置。
- 更新设计与验证文档中的实际状态和未验证项，不自动提交。

**交付物**：默认玩家可直接测试的新普攻、配置备份、验证记录和已知限制。

**验收条件**：第 1～9 步全部完成；Editor / Game 常规构建通过；修改蓝图编译和重载通过；默认地图单人/双人及方案 A 的拒绝收敛检查通过；工作区差异与本任务相关、无测试设置残留。Cook/打包单独安排，不把 Game 构建描述为打包通过。

## 后续阶段，单独立项

- 组合触发 B：命中事件与缓存输入组合，明确先后、关联和消费规则。
- 网络方案 B：有限容差、历史窗口核验和高延迟体验，独立验收。
- Section / 跳转 / 循环：定义事件补发、重复副作用和窗口重建语义后再开放。
- 图形技能编辑器：复用 Definition、DataTable、Timeline 和同一套校验；不另造需要手工同步的运行数据。

## 各阶段通用验证与当前进度

所有步骤目前均为**待执行**，没有因本文创建而完成任何实现阶段。

每个涉及 C++ 的可交付批次按 [AI 开发流程](../AI_DEVELOPMENT.md) 执行 Editor 构建；涉及 Runtime 或依赖时同时执行 Game 构建。反射/继承修改必须安全关闭编辑器后常规构建，Live Coding 不替代验收。失败先解决首个有效错误，再推进下一依赖阶段。

资产修改分别记录编译、保存、重新加载和 PIE 结果。测试聚焦实际行为风险，不为简单配置复制大量与实现同构的测试。全过程不升级引擎、不额外拆 Runtime 模块、不自动提交。

本次只创建执行计划并从设计文档建立链接；执行文档链接、格式和差异检查，未运行构建、PIE 或联机测试。
