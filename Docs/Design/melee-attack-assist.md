# 近战索敌与攻击吸附设计

日期：2026-10-08。适用 UE 5.5.4、现有 Hodgepodge Runtime 模块及动画通知驱动攻击链路。

**状态：设计草案，尚未实施。** 拟议类型、字段、GameplayTag、插件接入和资产改动均未创建。当前事实见第 2 节；示例参数只用于说明，验收均待执行。本文不声称复刻《鬼泣》《战神》的内部实现。

关联设计：[受击系统](hit-reaction-system.md)。现有配置以[攻击能力配置手册](../Guides/attack-ability-configuration.md)为准，动画时机继续在 Montage 通知轨制作。

## 1. 目标与基本原则

没有合适敌人时正常出招；有合适敌人时，起手阶段有限修正朝向与接近距离；手动锁定时优先围绕锁定目标出招。减少合理范围内的距离／朝向误差，同时保留方向输入、敌人闪避、障碍和技能距离的作用。

分别维护三种目标：

- 持续锁定目标：玩家明确选择，供锁定 UI、摄像机及技能参考。
- 本次攻击辅助目标：这一刀用于朝向和接近的目标，可能来自持续锁定或自动筛选。
- 实际命中目标：当前检测真正碰到并通过资格检查的目标，可能为多个。

锁定不保证吸附，吸附不保证命中。目标离得太远仍可保持锁定，但普通攻击不得因此自动冲到远处。范围横扫靠近 A 后可实际命中 A、B，也允许 A 躲出范围导致落空。

首版只处理普通地面近战辅助。完整锁定摄像机、处决站位、自动绕障寻路、复杂空中追踪和长距离突进分别按阶段扩展。

## 2. 已核实的当前基础

本节基于当前源码与配置；本次未核实二进制蓝图内部配置或运行效果。

- [HodgeGameplayAbility_Definition](../../Source/Hodgepodge/Private/AbilitySystem/Abilities/HodgeGameplayAbility_Definition.cpp) 负责执行身份、Montage、通知状态及结束清理。连段授权继续由 CombatComponent 管理。
- [HodgeGameplayAbility_Melee](../../Source/Hodgepodge/Private/AbilitySystem/Abilities/HodgeGameplayAbility_Melee.cpp) 提供服务器 `PrepareHitExecutionContext`、`SetHitTarget`、`SetHitAnchor`；前两者不是客户端通用索敌／预测入口，后两者不会自动移动或转向角色。
- [命中配置](../../Source/Hodgepodge/Public/Combat/HodgeHitDetection.h) 支持范围内任意目标、范围内指定目标、服务器确认目标等策略。真实刀击是否命中不能被辅助目标选择替代。
- [HodgeCharacterRotationComponent](../../Source/Hodgepodge/Private/Component/HodgeCharacterRotationComponent.cpp) 已有 Yaw 锁定与恢复；[HodgeCharacterMovementComponent](../../Source/Hodgepodge/Private/Component/HodgeCharacterMovementComponent.cpp) 在最终移动入口约束胶囊 Yaw，锁定期间也会限制根运动旋转。
- [HodgeCameraComponent](../../Source/Hodgepodge/Public/Camera/HodgeCameraComponent.h) 当前 `GetTargetActor` 返回 Owner；这个摄像机观察主体接口不能直接当作敌人锁定服务。
- 当前 [.uproject](../../Hodgepodge.uproject) 显式启用 AnimationWarping，没有显式启用 MotionWarping；[Build.cs](../../Source/Hodgepodge/Hodgepodge.Build.cs) 没有 MotionWarping 依赖。本机 UE 5.5 MotionWarping 插件默认关闭。
- 本机 UE 5.5 GameplayAbilities 已有 ApplyRootMotionMoveToForce／ApplyRootMotionMoveToActorForce Task，可作为位移执行候选。

未查到完整的原生近战软索敌、持续敌人锁定或攻击吸附链路。AnimationWarping 的步幅／姿势调整不代表 MotionWarping 攻击接近已实现。角色蓝图可能覆盖默认朝向配置，实施前必须核实正式 Pawn 与动画资产。

## 3. 推荐职责划分

### 3.1 目标服务

建议新增 Pawn 级 `UHodgeCombatTargetingComponent`，维护持续锁定、候选查询、评分、目标保持和失效通知。名称为拟议名称。

服务返回目标与选择原因，不造成伤害、不直接移动 Actor，也不成为第二套能力调度器。通过现有 Experience／PawnData 生命周期接入；避免默认子对象和 Experience 同时创建两份组件。

软锁定的本次目标属于执行上下文；持续锁定属于 Pawn 的战斗选择状态。UI 只展示显式锁定，软锁定无需强制显示标记。摄像机可以消费持续目标，但不负责决定每刀伤害对象。

### 3.2 攻击执行

Definition 提供每招辅助规则，GA 在起手前获取本次上下文，并拥有转向请求和运动资源。结束、打断、连段切换时释放本次资源。

不在每个蓝图 GA 中复制一套搜敌算法，也不把辅助逻辑塞进碰撞检测 Profile。Profile 继续负责检测查询与几何过滤。

### 3.3 朝向与运动

朝向请求由现有 RotationComponent 的扩展统一仲裁；控制器、移动朝向、目标朝向和根运动旋转不能每帧分别写胶囊旋转。

运动执行沿用 CharacterMovement。带前进根运动的动作优先评估 MotionWarping，原地动画可使用 Root Motion Source 接近；每招明确主要位移来源，不无意同时叠加两套完整前进量。

## 4. 拟议配置与运行上下文

以下为新增设计语义，不是现有编辑器字段。Definition 作为默认配置入口，专用辅助区间可在 Montage 使用拟议通知；不重新建立 Timeline 资产。

### 4.1 每招配置

- 是否启用自动索敌、辅助转向、辅助接近。
- 自动索敌半径／半角、最大高度差、遮挡查询规则。
- 最大辅助转角／转速；辅助转向和接近的动画区间。
- 最大接近距离、最大速度／加速度、理想攻击间距及近距离停止规则。
- 手动锁定优先策略、锁定超出本招范围时的回退策略。
- 当前刀目标是否保持、是否允许下一刀继承、目标切换优势阈值。
- 起手期间目标位置更新规则、停止更新时机和单次更新限制。
- 地面／空中适用条件、需要的目标战斗锚点。
- 无目标、目标失效、阻挡和运动未完成时的出招行为。
- 位移执行方式及普通 Root Motion 与辅助补偿的组合规则。

普通轻击、重击、突进和挑飞分别配置。普通攻击只补偿有限误差，突进采用专门动作与更长运动，不把小迈步动画拉成数米冲刺。

### 4.2 本次执行上下文

记录源 AbilitySpec／执行身份、当前 Avatar、候选／确认目标、目标选择来源、起手意图、计算站位、目标 Yaw、允许更新截止点、朝向请求句柄、运动句柄与终止原因。

跨端关联使用现有激活 PredictionKey／合法请求身份，不假设客户端和服务器独立生成的本地 ExecutionId 天然相同。预测目标与服务器确认目标分别记录，不能覆盖后丢失校正依据。

目标使用弱引用，访问前验证存活、阵营、世界和当前 Avatar；跨帧运行数据属于当前执行，不保存在共享 Notify 对象或配置资产上。

## 5. 自动索敌与持续锁定

### 5.1 候选过滤

攻击开始按本招范围做空间查询，归并到可攻击 Avatar。首版不每帧全场扫描，也不遍历所有 Actor 作为正式实现。

过滤自身、友方、死亡／无效目标、超过半径／角度／高度差者及被遮挡者。可见性与实际移动可达性分别检查：看得见不代表胶囊能直线接近。

锁定目标的 UI 可使用更大的有效范围，但每次攻击仍需通过本招辅助资格。锁定存在却不适合普通攻击时，默认保留锁定、停止该次接近并按允许角度出招；不偷偷吸附到旁边敌人。允许换目标的技能须显式声明。

### 5.2 玩家意图与评分

有有效方向输入时，优先使用该输入在世界中的方向；没有输入时采用配置规定的角色／摄像机前向。屏幕中央接近程度可以作为辅助分数，不能覆盖明确的反向输入。

评分组合距离、相对意图角度、屏幕位置、上一刀目标保持和显式优先级。各分量先归一化，距离单位不能直接与角度分值相加。锁定资格与硬过滤先处理，不仅靠巨大权重绕过范围。

相同评分使用稳定次序；服务端权威选择，客户端预测不要求跨机器遍历顺序完全一致。上一刀目标仅在仍合法且玩家没有明确改向时获得保持优势。

### 5.3 目标保持与切换

首版每刀起手选择一次目标，并保持 Actor 身份到该刀结束；起手中可更新其位置，不因位置变化改选另一个敌人。下一刀根据新输入重评估，允许玩家主动切换。

持续锁定单独提供获取、解除和切换请求，切换采用屏幕／方向关系与滞回规则。目标死亡、离开有效范围或长时间遮挡后解除／保留锁定的策略显式配置，不在当前刀中无条件转追其他目标。

## 6. 接近点与转向计算

接近点不是敌人 Actor 中心。首版对一般角色使用目标战斗锚点和沿当前接近方向计算的站位；大体型目标可提供可攻击锚点或表面距离策略。

以同一地面平面上的一般角色为例：

```text
u = 从玩家指向目标锚点的水平单位方向
期望玩家根位置 = 目标锚点 - u × 理想中心间距
需要补偿的接近距离 = max(0, 当前水平距离 - 理想中心间距)
```

这是几何示意，不是完整代码。理想间距综合双方碰撞体、武器有效距离、动作伸展和安全余量。目标已在近距离时默认只转向，不为了保持精确间距把玩家自动拉远。

接近距离限幅后，候选落点仍需胶囊空间和地面支持检查；无法到达则缩短或放弃接近。禁止穿墙、进入明显不支持的地面或无意把角色拖下悬崖。首版不自动寻路绕障，阻挡时允许按当前位置挥刀。

地面辅助以水平运动和 Yaw 为主，不直接追到目标任意 Z。目标腾空后，本次地面攻击按规则失去接近资格；专门的空中追击另行计算高度。

## 7. 动画时序与朝向仲裁

```text
攻击输入／服务器授权
  → 确定本刀目标和站位，建立本次辅助请求
  → 起手窗口内有限转向／接近，可有限更新目标位置
  → 挥刀前冻结或收紧追踪，进入现有朝向锁
  → 正常命中窗口按真实几何检测
  → 收招恢复正常朝向，清理本刀辅助资源
```

这些阶段使用 Montage 源时间和实际实例上下文，随播放速度、暂停、跳转和取消变化；不能以固定墙钟延时替代动画窗口。窗口上下文验证继续沿用已有 GA／实例身份模式。

建议优先级为：死亡／强受控限制与已有最终 Yaw 锁高于普通攻击辅助；辅助仅在获准窗口提供目标朝向，正常控制器／移动朝向在无请求时接管。需要受击改变朝向时，由受击接管流程释放冲突的旧攻击请求，不绕开约束硬写旋转。

目前 Yaw 锁会约束 MotionWarping 的根运动旋转。因此辅助转向应在锁开始前完成；若某招要持续转向到更晚，明确调整其窗口，并验证武器轨迹，不能偷偷屏蔽全局锁。

正式 Pawn 可能使用 ControllerYaw，源 C++ 默认也可能被蓝图覆盖。接入时核实实际驱动方式，不能只改 `OrientRotationToMovement` 就宣称所有角色能朝目标转向。镜头输入继续独立，不因角色短暂面向目标而强行旋转镜头。

## 8. 位移执行方案

### 8.1 带前进根运动的动作

推荐在有限起手区间使用 MotionWarping，给出合法的目标变换，对现有根运动做接近／旋转调整。窗口在接触前结束或收紧，避免挥刀后继续滑向目标。

启用插件、添加 Runtime 依赖、组件和通知均属于未来实施范围。本次不修改 .uproject 或 Build.cs。公开头文件若暴露 MotionWarping 类型，需核实依赖可见性，不能只添加 Editor 条件依赖。

动作必须有适合调整的根运动轨迹，不能仅勾选 EnableRootMotion 就假设原地动画具备自然的前进。无有效目标时不创建辅助 Warp Target，保留原动作；上一刀目标必须清理，不能沿用过期变换。

### 8.2 原地动作与专门接近

可使用现有 GAS Root Motion Source Task，按合法落点／目标偏移施加短时运动，并配置时长、路径／时间曲线和结束速度。

运动曲线与脚步、起手阶段配合。接近完成后不要残留突进速度；被打断时释放属于本执行的运动源。MoveToActor 具备目标更新能力，不代表可以全程无限追踪；仍受本招窗口与更新限制约束。

### 8.3 移动目标

首版仅在起手窗口更新目标站位，限制目标变化速度、最大修正距离和角度。挥刀前冻结位置／朝向；敌人后续快速闪避可以让攻击落空。

目标突然瞬移、失效、被击飞或越出限制时停止辅助，按技能配置完成剩余动作；不为了追上而无限增速。Sweep 碰撞决定实际位移，Warp 目标不是必达位置承诺。

## 9. 与伤害和受击的边界

辅助上下文不直接调用伤害效果。真实命中继续沿用 Melee GA、检测 Task、去重和 GE 链路。

- 普通范围刀击继续检测范围内合格目标，辅助目标不排除其他碰到的敌人。
- 单目标刀击可将确认后的目标提供给 LockedTargetInVolume，仍要求空间命中。
- ConfirmedTarget 保留给设计明确允许直接确认的特殊技能，不作为“保证吸附命中”的补丁。
- 本次辅助目标与实际命中集合分别记录，用于调试和追击选择。

受击打断攻击时，攻击的 EndAbility 同时关闭命中窗口与辅助运动／朝向请求。已确认的目标受击轨迹不得反过来每帧拖动玩家，只有专门追击技能允许接近。

挑飞范围攻击可以有多个成功目标。追击主目标只从服务器确认“攻击判定等级大于等于目标 Body 等级，且 Launch Impact 实际成立”的集合中选：优先本次辅助目标，其次合法的稳定前向／距离规则。等级未通过、命中被拒绝或 Launch 因适用性被跳过时，不能启动成功追击分支；不得把配置了挑飞视为挑飞成功。具体等级与 Impact 契约见[受击系统](hit-reaction-system.md)。

## 10. 网络、预测与生命周期

目标伤害仍由服务器检测和结算。吸附涉及玩家移动，首版需要拥有者即时预测与服务器核验，不能只在服务器 `PrepareHitExecutionContext` 中选目标再等待客户端被位置纠正。

拥有者可提交候选目标和攻击意图；服务器重新验证目标、范围、角度、阵营、遮挡及允许接近量。客户端提交的目标不是伤害或位移授权，服务器不接受任意目的坐标。

服务器难以直接复现客户端屏幕中心，因此屏幕分数可用于客户端候选提议，权威资格使用可信输入和世界几何；预测候选被拒绝时回退合法目标或正常出招。服务器结果通过现有激活身份关联本次执行，在允许窗口校正；超过窗口停止辅助并沿用移动校正，不在挥刀中途无限换方向。

与现有 ComboCoordinated 的服务器授权、Standalone 的预测执行分别接入，保持各自契约。目标服务可以先收集意图，但不自行激活连段，不能绕过 CombatComponent 授权。

实施前明确辅助目标、起点、窗口和运动参数如何进入激活／同步上下文；自定义状态若影响移动重播，须纳入 SavedMove 或运动源对应机制。不能把复制一个 TargetActor 当成完整预测支持，也不能假设服务器单独创建所有运动源就自动正确控制拥有者。

模拟代理消费服务器角色运动和必要动画状态，不独立重新索敌并修改复制位置。持续锁定标记按 UI 需要同步；攻击运动所需状态必须让相关观察者得到，不能只依赖拥有者界面状态。

玩家 ASC Owner 保持 PlayerState，锁定和辅助上下文绑定当前 Pawn。重复初始化幂等，解绑、死亡、目标销毁、武器切换、连段切换和 EndPlay 清理对应句柄／委托。结束旧刀不能清除新刀或其他能力的资源；共享 Warp Target 名称须有执行所有权保护。

## 11. 调试与参数迭代

提供按需绘制：候选扇区、拒绝原因、评分、锁定／辅助／实际命中目标、理想站位、限幅落点、更新截止点、实际轨迹和碰撞停止点。

记录攻击身份、预测／权威目标差异、朝向请求优先级、运动结束原因。沿用现有调试开关风格，避免每帧无条件日志。

调参依次处理：目标是否符合意图、转向是否及时、接近是否适量、挥刀是否停止追踪、命中与动画是否一致。不要先扩大命中体掩盖错误的索敌／运动。

教学示例可以设置小范围转向和短距离补偿，但正式数值应针对当前模型、武器、动画、键鼠／手柄以及敌人体型实测，不作为全角色固定值。

## 12. 实施阶段与验收

### 阶段 A：软索敌与起手转向

- 实现候选过滤、输入意图、每刀目标保持和有界朝向请求。
- 验收：无怪可正常攻击；前方多个怪不抖动换目标；明确改向可在下一刀换目标；背后怪不无条件抢目标；锁定期间的攻击朝向与最终 Yaw 锁一致。

### 阶段 B：地面有限接近

- 根据正式动画选取 MotionWarping 或 Root Motion Source，加入合法站位、窗口和运动清理。
- 验收：近距离不穿入目标；远处不超普通攻击上限；墙体、悬崖、天花板／高度差不导致非法接近；敌人闪避能正常落空；打断和连段切换不残留旧目标或运动。

### 阶段 C：持续锁定与连段目标保持

- 增加玩家锁定输入、标记和切换；摄像机作为独立消费者接入。
- 验收：有效锁定优先；超出本招范围仍可原地出招，不偷偷改打邻怪；死亡／失效按策略解除；镜头与角色朝向不互相争夺。

### 阶段 D：空中追击

- 与受击系统连接确认成功的挑飞结果、主目标选择、玩家升空和空中有限接近。
- 验收：多目标只追一个；落空／免疫不误触追击；玩家与目标保持独立碰撞；高度／速度有界；下砸或目标失效时能正常结束。

原生测试重点覆盖筛选／评分、目标保持、边界／限幅、旧执行清理和服务器拒绝。实施后按开发约定执行 Editor 与 Game 常规构建，再分别验证正式 Pawn／动画蓝图、单人 PIE、双人 Listen Server、延迟／丢包／位置校正、模拟代理和 Pawn 更换。
